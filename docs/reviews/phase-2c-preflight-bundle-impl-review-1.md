## Findings

### [Low] `loadBaseline` validates `total_size_bytes` and `chunks` but not `total_size_gzip_bytes`

**Location:** `frontend/scripts/check-bundle-budget.ts:125-136`

The guard at lines 125–130 checks that `total_size_bytes` is a number and `chunks` is an array, but does not check `total_size_gzip_bytes`. `compareAndPrint` uses `baseline.total_size_gzip_bytes` at line 144. A baseline JSON that has `total_size_bytes` and `chunks` but is missing `total_size_gzip_bytes` would pass validation, but `computeDelta` would receive `undefined` as its first argument, producing NaN in the gzip delta row (`NaN KB (NaN%)`).

In practice this is low risk because the baseline is always generated by `capture-bundle-baseline.ts` (which includes all fields), and the comparator is advisory. A one-line addition to the guard (`typeof (parsed as Baseline).total_size_gzip_bytes !== "number'`) would close it.

### [Low] `walkDist` calls both `readFile` and `stat()` per file — `stat()` is redundant

**Location:** `frontend/scripts/check-bundle-budget.ts:84-85`

`readFile` returns a Buffer whose `.length` equals the file size in bytes for text files. The subsequent `stat()` call on the same path fetches the same information via an extra syscall. `contents.length` could replace `(await stat(full)).size` with no behavior change, eliminating one async syscall per file.

Impact is negligible for the current ~5-file dist, but it's a small unnecessary cost that also makes the reader wonder whether there's a semantic difference between the two sizes (there isn't for `.js`/`.css`).

### [Nit] `compareAndPrint` re-computes `baseName()` in added/removed filters

**Location:** `frontend/scripts/check-bundle-budget.ts:208-209`

The `added` and `removed` filters call `baseName(c.file)` per element, but `baselineByKey` and `currentByKey` already hold the stripped keys. The added/removed computation could use the map key sets directly (or build a `Set<string>` of the map keys), avoiding redundant regex work. Immaterial for ~5 files, but the maps are right there.

### [Nit] Spec §3.5 estimated ~150 LOC for comparator; actual is 247

**Location:** `frontend/scripts/check-bundle-budget.ts` (full file), spec `specs/19-frontend-phase-2c-preflight-bundle-design.md:185`

The spec's §3.5 file table estimated ~150 LOC for `check-bundle-budget.ts`. The actual file is 247 lines. The overshoot is from `compareAndPrint`'s console-formatting logic (table rows, padding, conditional sections), which is inherently verbose — not from scope creep. No action needed; noted for estimate calibration in future specs.

### [Nit] `.prettierignore` commit bundles a supporting change that wasn't in the plan's task list

**Location:** `frontend/.prettierignore` (commit `4b39840`)

The plan's Task 5 (fixtures + loadBaseline tests) didn't mention updating `.prettierignore` to exclude the malformed JSON fixture. This was correctly handled as a separate commit (`chore(fe): exclude bundle-comparator malformed JSON fixture from prettier`), and the exclusion is necessary, but it represents a plan gap — the task should have called out the prettier exclusion step. No code issue; just a planning completeness note.
