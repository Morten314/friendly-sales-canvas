## Task 4: Deduplicate `llm_config.py` near-identical prompts

**File:** `app/core/llm_config.py`
**Estimated savings:** ~160 lines (from 342 → ~182)

`Cypher_gen_prompt` and `Cypher_gen_prompt2` are ~95% identical (only difference: prompt1 has the `original_json`/`modified_json` paragraph at lines 103-104). `qa_prompt_template` and `qa_prompt_template2` are ~90% identical (only difference: template1 has 5x repeated JSON instruction lines at 134-138).

**Approach:**
1. Create one `_CYPHER_BASE_PROMPT` with the shared schema/relationships/rules body.
2. `Cypher_gen_prompt` = `_CYPHER_BASE_PROMPT` + the extra paragraph.
3. `Cypher_gen_prompt2` = `_CYPHER_BASE_PROMPT` (no extra paragraph).
4. Create one `_QA_BASE_PROMPT` without the repeated JSON lines.
5. `qa_prompt_template` = `_QA_BASE_PROMPT` with the JSON repetition block inserted.
6. `qa_prompt_template2` = `_QA_BASE_PROMPT` as-is.

This eliminates ~160 lines of duplicated schema definitions and prompt text.

**Verification:** `python -c "from app.core.llm_config import build_llm_config; print('OK')"`

## Task 5: Collapse 5 duplicate `Research_Market_N` functions

**File:** `app/services/market_research/orchestrator.py`
**Estimated savings:** ~100 lines (from 288 → ~188)

Research_Market_1 through Research_Market_5 (lines 36-181) are identical except for the template constant they use. Each repeats the same ~25-line body: pre_data normalization → template selection → format → LLM call → parse JSON → return.

**Approach:**
1. Create `_run_research_component(agent_chain, pre_data, template, llm_backend)` with the shared body.
2. Replace `COMPONENT_FUNCTIONS` dict to map component names to template constants.
3. Replace `COMPONENT_FUNCTIONS_CLAUDE` dict with a single `COMPONENT_TEMPLATES` dict (backend selection happens at the call site in `run_market_research`).
4. Delete all 5 `Research_Market_N` function definitions.
5. Update `run_market_research` to call `_run_research_component` directly with the looked-up template.

**Verification:** `python -c "from app.services.market_research import run_market_research; print('OK')"`

## Task 6: Extract shared `fetch_company_profile` helper

**Files:** `app/services/_neo4j_helpers.py`, `app/services/market_research/orchestrator.py`, `app/services/icp/orchestrator.py`, `app/services/customer_profile.py`
**Estimated savings:** ~30 lines

Three copies of the same Neo4j query (`MATCH (c:CompanyProfile {org_id: $org_id}) RETURN c LIMIT 1` with fallback to unfiltered). Two also include the `socialMediaUrls` JSON parsing.

**Approach:**
1. Add `fetch_company_profile(driver, org_id: str | None) -> dict | None` to `_neo4j_helpers.py`. It runs the Cypher query, parses `socialMediaUrls`, and returns a clean dict (or None).
2. Replace all 3 call sites to use the shared helper.
3. Remove the nested `def fetch_company_profile()` definitions in `market_research/orchestrator.py` and `icp/orchestrator.py`.

**Verification:** `python -c "from app.services._neo4j_helpers import fetch_company_profile; print('OK')"`
