# Org Null-Safety + Profiler/ICP Integrity — Design Spec

**NN:** 48
**Date:** 2026-07-09
**Status:** Design intent (output of brainstorming). Frozen record — code is authoritative after merge.
**Origin:** RCA of five bug reports from tester Ishani (Firebase uid `YlVahyxE7JORAk3IuxHlcWE6Mnr2`, org `2b4bfc67-4831-47ff-915d-319a6b83829c` / `brewra_ishani_1`), 2026-07-09: (1) deleted suggested ICP reappears, (2) Profiler Lead Stream shows no leads, (3) Profiler shows previously-generated data with no ICP saved, (4) Mission Control settings reset on login, (5) Company/Customer Profile empty while Data Sources populated. **Predecessor:** `specs/46-org-tenant-reunification-design.md` (merged). Spec 46 collapsed the frontend `tenant` abstraction into the single authoritative `org` (`useOrgId()` backed by `AuthContext`, `GET /org` authoritative) and added a backend 1:1 user↔org invariant + a `reconcile_orgs.py` data-recovery script. **This spec does not re-open tenant work.** It closes the residue spec 46 left behind — the `orgId || "brewra"` literal coalesce and the unguarded org-resolution race — and fixes three adjacent Profiler/ICP logic defects.

## Overview

Spec 46 made org *resolution* authoritative, but two things survived it:

1. **Org-fallback literals** — chiefly the `orgId || "brewra"` coalesce, present verbatim in **22 sites** across Mission Control, the Profiler (Customers), Settings, and Market Research, plus a sibling `orgId ?? "org-123"` family in **3** signals/chat write sites. Both placeholders are truthy, so they defeat the downstream `enabled: !!orgId` query guards and turn *"org not resolved yet"* into an **active read/write against a placeholder tenant** (`"brewra"` or `"org-123"`). This is distinct from the tenant fallback spec 46 removed.

2. **The org-resolution race** — `AuthContext` resolves the real org asynchronously (`void fetchOrgId(user.uid)`, fire-and-forget) and gates rendering only on `loading`, so org-scoped surfaces first render with `orgId === null`. Combined with (1), a null org is silently redirected to `"brewra"`.

Together these scatter a user's data across their real org and the legacy `"brewra"` org, and make the Lead Stream / Mission Control render against the wrong (or a null) tenant during the login window.

This spec also fixes three Profiler/ICP defects that are independent of org identity but were surfaced in the same report: id-only ICP dismissal that can't survive regeneration (#1), an empty-vs-error conflation that re-hydrates deleted ICPs (#3), and a company-profile hook that renders a server outage as an empty form (#5, FE half).

**#3 — Stale ICPs shown with no ICP saved (CONFIRMED).**
`SuggestedICPCards.tsx` `loadProfilerPagePayload` gates the stale `customerProfile` localStorage fallback on `icps.length === 0` (`:122`) and swallows the read-error throw (`:119`) — so an *empty* profile is treated identically to a *failed* read and re-hydrates previously-deleted ICPs from cache (`:126`, mapped in at `:129-132`, rendered via `existingICPs`). Compounding: the `customerProfile` org cache is never cleared on delete (`refetchCustomerProfileIcps` writes only when `rows>0`; `ICPManager.tsx` early-returns on a zero-ICP save; `removeOrgLocalStorage` is only ever called for `customerProfile_pending`). Second vector: the module-level session snapshot short-circuit (`SuggestedICPCards.tsx:460-472`) can restore stale `existingICPs`. Incomplete-fix gap left by `d716bc2c`.

**#1 — Deleted suggested ICP reappears (CONFIRMED core).**
Rejection is defended by ICP **id** on both sides: the client dismissal is an id-`Set` filtered by `filterDismissedFromSuggested` (`suggestedIcpStorage.ts:97`), and the backend `delete_recommended_icp` matches by `str(icp.id) == icp_id` and rewrites the doc (`persistence.py:260-302`). A header **Refresh** → `GET /v2/icp?refresh=true` → `list_icps(refresh=True)` regenerates: the LLM omits ids (prompt `icp_generator.md.j2:50`), `_reserve_unique_icp_id` mints a fresh `uuid4` per ICP (`persistence.py:71`), and `update_one` **overwrites the whole ICP_config doc** (`persistence.py:239`). The re-created "same" ICP carries a new id that neither the overwritten server doc nor the id-keyed client filter can suppress. No content-based dedup exists anywhere. Secondary hole: `finalizeRecommendedReject` removes the pending-reject record *before* awaiting the DELETE (`SuggestedICPCards.tsx:690`); a non-404 DELETE failure then records no dismissal and the card returns on the next load.

**#5 — Company/Customer Profile empty, Data Sources populated (CONFIRMED FE amplifier; symptom otherwise a migration artifact).**

The FE swallow-5xx behavior and the latent per-user guard remain real code risks worth removing.

## Goals

1. A null / unresolved `orgId` **never** reads or writes a placeholder tenant, and org-scoped UI **never renders against a null org** — it defers (loading) or shows a clear no-org state.
2. Removing the org-fallback literals is **complete** — all 22 `|| "brewra"` sites **and** the 3 `?? "org-123"` sites — so the org divergence cannot recur through this path.
3. An empty backend result and a failed/again-unavailable read are **distinguishable** everywhere they drive Profiler UI — neither re-hydrates stale data nor blanks a populated form.
4. A rejected recommended ICP **stays dismissed across regeneration** — durably, per-user, and **best-effort** (content-signature; see WS3 for the accepted false-negative / false-positive bounds).

## Non-goals (explicitly out of scope)

- **Prod data reconciliation.** Ishani's split data will be resolved by **deleting her account + related data and re-creating it**, not by migrating on prod. `reconcile_orgs.py` (spec 46 WS3) is not run here.
- **Org auto-provisioning / the onboarding org-mapping gap.** Signup is Firebase-only and does not create an org; mapping stays a manual admin step. This spec handles a no-org user *gracefully* (a neutral state) but does not auto-provision.
- **TD-016 Neo4j cold-start retry.** The backend root cause of the #5 blip (raw `session.run` with no transient retry) stays its own tracked resilience item. This spec fixes only the FE amplifier.
- **Multi-tenant / multi-org.** Backend remains 1:1 user↔org (spec 46).
- **Re-opening tenant resolution** (spec 46, merged).

## Architecture

Four workstreams. WS1 is the org-safety forward-fix; WS2/WS4 are localized FE data-integrity fixes; WS3 is cross-stack (FE+BE, one atomic change).

### WS1 — Eliminate org-fallback literals + gate on resolved org  *(fixes #2, #4)*

**Decision: gate + per-surface guards (defense-in-depth).**

**(a) AuthContext — an explicit resolution state.**
- Model resolution as **three definitive-vs-transient outcomes**, not one boolean-with-timeout: (1) *resolved with org* → render the app; (2) *authoritatively resolved with no org* (a real 404 / empty 2xx from `GET /org`) → the no-org terminal state (f); (3) *transiently unresolved* (timeout, 5xx, network) → a distinct **"reconnecting" retry state**, never (f). Concretely, represent this as a **three-state `orgStatus`** (`resolved` / `no-org` / `transient`), **not** a single `orgResolved` boolean-plus-flag: a lone "resolved" boolean is true for *both* (1) and (2), which invites a route gate that mounts org-scoped UI for the no-org outcome and renders against a null org — the very failure WS1 exists to prevent. If a derived `orgResolved` convenience is retained (= outcomes (1)|(2), i.e. not transient), the render gate MUST still be the **has-org** predicate `orgResolved && orgId` (equivalently `orgStatus === "resolved"`), never `orgResolved` alone. `orgId` is `null` for (2) and (3). **Reset all of it on user change / logout — and guard against the stale-async variant of the fire-and-forget race this spec fixes: a late-arriving resolution or retry MUST be discarded if the user changed / logged out while it was in flight** (a uid/generation check, or cancel the in-flight `GET /org` on user change), so a stale response never mutates state for the wrong user.
- Gating lives at the **protected-route boundary** (see (e)): render org-scoped routes only on the has-org outcome (1) (`orgResolved && orgId`, equivalently `orgStatus === "resolved"`); outcome (2) renders (f); outcome (3) renders the retry affordance. Keep the optimistic-cache read (so a returning mapped user with a warm cache paints instantly), but a cold-cache or unmapped user waits on resolution rather than rendering against `null`/`"brewra"`. **A warm cached org counts as outcome (1) and survives a *transient* confirm-failure:** if the background `GET /org` then times out or returns 5xx/network error, the app stays mounted on the cached org and retries in the background — it is **not** torn down into the (3) reconnecting state (which would flicker the app away from the most common user on any blip). Outcome (3) is reached only when there is **no usable cached org** to fall back on.
- **No infinite spinner, and no false "no workspace."** A hung / never-answering `GET /org` (a cold Render free-tier instance can exceed 8–10s on first hit; a network stall) must neither spin forever *nor* be reported as no-org. A bounded timeout with at least one auto-retry / backoff converts a hang into outcome (3) — a visible, actionable "having trouble reaching your workspace — retrying" state, which *is* the convergence guarantee (the round-1 infinite-spinner fix). Only outcome (2) shows "contact your admin," so a slow-but-valid resolution for a mapped user is never mislabeled. **The reconnecting state is itself bounded:** retries back off up to a max-retry ceiling, after which auto-retry stops and a manual affordance (*try again* / *sign in again*) is offered rather than reconnecting forever (stated so the plan does not ship an unbounded retry loop; acceptable-at-MVP otherwise).
- **The cold-cache wait is bounded and covered.** Gating on `orgResolved` means a cold-cache (or unmapped) user now blocks on a `GET /org` round-trip before any org-scoped UI paints — a perceived-latency cost versus today's instant-but-wrong paint. Mitigate with a shell-level skeleton / branding during `!orgResolved` (non-org chrome may paint optimistically); the target is a sub-second warm path, with the (a) timeout as the hard ceiling.
- Preserve spec-46 authority: a **successful** `GET /org` still wins over cache (a resolution that disagrees with the cached org overrides it) — but a *transient non-resolution* is not a "win" and must not discard a usable cached org (see the outcome-(1) cache-retention rule above); logout still clears `org_id_<uid>`.

**(b) Remove *every* org-fallback literal — not only the `"brewra"` ones.** The completeness target is any `orgId || "…"` or `orgId ?? "…"` resolving to a **non-empty placeholder tenant**, enforced by a **grep sweep at plan time** (search `orgId ||` / `orgId ??` followed by a non-empty string literal — `?? ""` is fine, an empty string makes the query defer) rather than a hand-list that can silently miss a sibling. Two live families exist (verified 2026-07-09):
- **`|| "brewra"` — 22 sites:** `settings/components/CompanyProfile.tsx:53`; `customers/.../SuggestedICPCards.tsx:301,310,311,313,348,382,443,525,705`; `mission-control/.../DataSourcesManager.tsx:31,103,168`; `mission-control/.../ICPManager.tsx:48`; `mission-control/.../CompanyProfileForm.tsx:52`; `mission-control/pages/MissionControlPage.tsx:55`; `market-research/.../{RegulatoryCompliance,MarketEntry,MarketSize,IndustryTrends,CompetitorLandscape}Section.tsx`; `market-research/hooks/useMarketResearchData.ts:335`.
- **`?? "org-123"` — 3 sites (org-scoped writes into signals/chat):** `market-research/.../scout-chat/ScoutChatPanel.tsx:259`; `shared/chat/ContextChat.tsx:97,176`. Each POSTs `org_id: orgId ?? "org-123"` when `orgId` is null, so Goal #1's "never a placeholder tenant" is not met until they too are removed.
Each becomes the real, nullable `orgId`. (Cosmetic-only sibling, no data-integrity risk: `shell/components/ProfileDialog.tsx:18` `orgId ? \`${orgId}.com\` : "brewra.com"` — a display domain string; fold it in while sweeping.)

**(c) Reads defer.** `useICPs`/`useDataSources`/`useLeads` already carry `enabled: !!orgId`; they now actually defer. **Add the missing `!!orgId` guard to `useCompanyProfile`** (`useCompanyProfile.ts:20`), and to any other org-scoped query that lacks one.

**(d) Writes never fire null — including *transitively*-coalesced ones.** Guard every mutation and org-scoped `localStorage` write (SuggestedICPCards reject/accept/save handlers, ICPManager saves, DataSources writes) so nothing is persisted under a null/placeholder org. **Call out the lead-upload chain explicitly** (it is the #2 data-split write vector, and it hides behind a prop rather than a literal): removing the `|| "brewra"` at `DataSourcesManager.tsx:31` is necessary but *not sufficient*, because `useLeadStream` takes `orgIdToUse` as a prop and writes it verbatim in `uploadCsvBatch` (`useLeadStream.ts:325,350` → `POST /leads/batch-upload`) and in the file-scoped write at `:196–208`. Once the coalesce is gone that prop is a nullable org, so `useLeadStream` MUST itself refuse to upload — and the CSV control MUST be disabled — until `orgResolved && orgId`; otherwise the same upload merely shifts from writing `"brewra"` to writing `null`/empty. Enumerate this chain (and the Apollo-discovery / manual-add lead writes) in the plan rather than relying on the (b) literal-sweep, which cannot see a coalesce that has already been threaded through a prop. Enumerate too the sibling *direct* org-scoped uploads in the same file — `DataSourcesManager.tsx:111,177` (`formData.append("org_id", orgIdToUse)`, the document/PDF uploads consuming the `:103`/`:168` coalesces): removing those literals plus the general write-guard covers them, but naming them keeps the plan from treating the CSV chain as the *only* org-scoped upload write.

**(e) Per-surface null-safety (defense-in-depth, not the primary gate).** The authoritative gate is (a)'s check at the **protected-route boundary** — org-scoped routes do not mount until `orgResolved`, so in the normal flow a surface never sees an unresolved org, and the per-surface handling here is belt-and-suspenders. It is deliberate for the cases the route gate does not cover: a mid-session `currentUser` change that re-enters resolution while a surface stays mounted, and any surface reachable outside the gated route tree. Each org-scoped surface therefore renders a *loading* affordance while the org is unresolved (`orgStatus === "transient"`, i.e. `!orgResolved`) and a *distinct* empty state afterwards. Specifically, `LeadStream` must distinguish "org resolving / no org" from "genuinely zero leads" so it stops showing the misleading "No prospect data yet — upload a prospect list" for a merely-deferred query (`LeadStream.tsx:62`). (If the plan finds any org-scoped surface that can mount *before* the route gate — e.g. a late-resolving code-split shell — that surface's guard is load-bearing, not redundant, and must be treated as such.)

**(f) No-org terminal state — authoritative no-org only.** When `GET /org` *authoritatively* resolves to no org (a real 404 / empty 2xx — the onboarding gap), the shell renders a neutral, non-destructive **"Your workspace isn't set up yet — contact your admin"** state instead of wrong-tenant data. A **timeout / transient failure does _not_ reach this state** — it routes to the (a) "reconnecting, retrying" affordance, because a mapped user on a cold or slow backend is not an unprovisioned user and must not be told to contact an admin.

### WS2 — Profiler Current-ICPs: honor empty-vs-error  *(fixes #3)*

- In `loadProfilerPagePayload` (`SuggestedICPCards.tsx`): hoist `fetchCustomerProfileIcps` out of the signal-swallowing `try/catch` and track a `readFailed` boolean (mirroring the extractor's `sawSuccessfulRead`). Gate the `getOrgLocalStorage("customerProfile")` fallback on **`readFailed === true`**, not `icps.length === 0`. A successful-but-empty read renders an empty Current-ICPs table.
- Purge the resilience cache on empty-success: write `[]` / `removeOrgLocalStorage("customerProfile", org)` in the `refetchCustomerProfileIcps` empty branch, and stop `ICPManager`'s zero-ICP early-return from skipping the cache clear.
- Prevent the session-snapshot short-circuit (`SuggestedICPCards.tsx:460-472`) from restoring `existingICPs` the current profile no longer has (re-apply the empty-vs-error result before trusting the snapshot).

### WS3 — Recommended-ICP dismissal durability  *(fixes #1; cross-stack)*

**Decision: backend durable dismissed-set keyed by content signature.**

- **Signature — lowest-variance fields only, with an explicit stability bar.** Regeneration re-mints ids *because the LLM re-authors the suggestions*, and that same re-authoring drifts the content too — so the signature must be built from the **lowest-variance identity fields, canonicalized**, not from free text (a naïve `title`-inclusive signature would itself drift and re-surface the dismissed ICP — the very bug #1). Verified against the emitted schema (`prompts/icp/icp_generator.md.j2`): the fields are `title` (top-level, free-text) and `firmographics.{industry, segment, company_size, market_size}` (nested); `company_size` (e.g. "50–200 employees") and `market_size` are free-text ranges, and `confidenceScore` is enum-like but not identity-bearing. **Signature = canonicalized `firmographics.industry` + canonicalized `firmographics.segment`** — the two most identity-bearing, lowest-variance fields; **exclude `title`, `company_size`, `market_size`** as high-variance free text. Canonicalization: lowercase → trim → collapse internal whitespace → strip punctuation. **`firmographics.industry` is ~constant across a company's ICP set** (`icp_generator.md.j2:13,16,63` instruct every ICP to use the company's actual industry), so in practice **`segment` is the effective discriminator**; `industry` is retained only to scope the theoretical multi-industry edge case at ~zero cost. **Empty / missing signature ⇒ no suppression:** when `firmographics.industry`/`segment` are absent or blank (older docs, LLM omission), the ICP is neither recorded into nor matched against the dismissed set — a degenerate empty signature must never suppress every firmographics-less ICP. (These fields are nested under `firmographics` in the payload — the plan pins the exact accessor against the persisted doc shape.)
- **Residual-drift acceptance bar — both directions.** With `segment` as the effective discriminator, matching is best-effort and errs *both* ways: **(false-negative)** a regeneration that materially relabels the segment slips past and re-surfaces a dismissed ICP; **(false-positive / over-suppression)** two genuinely distinct ICPs that canonicalize to the same segment collapse to one signature, so dismissing one hides the other on every future refresh — and with no un-dismiss affordance in scope, that ICP is effectively lost. Both are **accepted at MVP / 0 users** (Goal #4 is durable *best-effort*, not exact): a re-surface is a cheap re-dismiss, and same-segment collisions within one company's small ICP set are expected to be rare. **Revisit trigger:** if over-suppression is actually observed, raise resolution with a still-low-variance discriminator (a bucketed `company_size` band or a canonicalized leading `title` token) before resorting to fuzzy / embedding matching (YAGNI until then).
- **Rejected alternatives (they share the same limitation).** (1) *Non-destructive `refresh=true` that preserves ids* — a genuine regeneration produces new suggestions with no prior ids to preserve, so it still needs a match key; doesn't escape drift. (2) *Persist a stable id at first generation + re-attach on content-match* — the "content-match" is this same drifting signature, merely relocated. (3) *Prompt-level exclusion ("don't suggest these")* — relies on unreliable LLM adherence; a post-filter is strictly more robust. The content-signature post-filter is chosen as the most robust option available given LLM-omitted ids.
- **Store — per-user, explicitly.** Persist the dismissed-signature set **keyed per-user** (matching the existing per-user suggestedICPs storage), on the `ICP_config` doc or a sibling field. Under the spec-46 1:1 user↔org invariant per-user and per-org coincide; keying per-user is the safe choice if that invariant ever loosens and removes the earlier "keyed by user/org" ambiguity.
- **Reject path.** `DELETE /icp/recommended/{id}` records the ICP's signature into the dismissed set (in addition to the existing id delete), reading the ICP's content from the current doc before removal.
- **Regeneration path.** `list_icps(refresh=True)` filters newly generated `suggestedICPs` against the dismissed set (by signature) **before** persisting/returning, so a re-created ICP is never re-surfaced.
- **Pre-deploy dismissals may resurface once (accepted).** The signature set starts empty at deploy; ICPs dismissed *before* deploy carry only an id (no signature), so the first post-deploy `refresh=true` cannot suppress them. At 0 users (and with the reporting account reset out-of-band) this is accepted with **no backfill**, consistent with the MVP no-migration posture — not a one-time signature backfill.
- **FE.** Close the non-404 DELETE-failure hole in `finalizeRecommendedReject`: do not remove the pending-reject record before the DELETE resolves; on a non-404 failure, keep/re-arm it rather than silently reverting. (Backend remains the source of truth; the existing FE id-filter stays as an optimistic in-session hide.)

### WS4 — Company-profile FE resilience  *(fixes #5 FE half)*

- `useCompanyProfile` (`useCompanyProfile.ts:24-34`): stop resolving 5xx/network/CORS errors to `null`. Let transient errors surface to react-query's `error` (with retry / keep last-known data); treat only a genuine 404 / empty 2xx as "no profile → empty form". This removes both the blank-form-on-outage and the risk of a subsequent empty save overwriting a real profile.
- **Remove the per-user guard on the org-owned profile** (`companyProfileMapping.ts:39`, `if (data.user_id && data.user_id !== userId) return null;`) and the mirrored guard in the localStorage failover (`CompanyProfileForm.tsx:95`). The company profile is org-owned; it must not blank for a different member of the same org. (Latent today — live payloads carry no `user_id` — but a correct, cheap removal while in this file.)

## Testing

Follow the repo gate: per-task `npm run verify` + `npx prettier --check` on touched files from `frontend/`, full `npm run preflight` before merge; backend `pytest` (`patch-where-used`, `backend/TESTING.md`), never the root-level live-probe `test_*.py`.

- **WS1:** AuthContext gating (**org-scoped routes mount only on the has-org outcome — `orgResolved && orgId` / `orgStatus === "resolved"` — so the authoritative-no-org outcome (2) renders the no-org state, never org-scoped UI against a null org**; `orgId` stays null on 404; **a hung/slow `GET /org` routes to the "reconnecting/retry" state — never an infinite spinner, and never the "contact your admin" no-org state (which shows only on an authoritative 404/empty)**; **a warm cached org survives a transient confirm-failure — the app stays mounted and retries in the background rather than tearing down into the reconnecting state**; **a resolution or retry that arrives after a user change / logout is discarded, not applied to the new user; and the reconnecting state stops at a max-retry ceiling with a manual retry affordance rather than retrying forever**); a representative org-scoped surface defers its query while unresolved and does not read `"brewra"`; **the `?? "org-123"` chat/signals writes defer instead of POSTing `org-123` when `orgId` is null**; **`useLeadStream.uploadCsvBatch` refuses to upload (and the CSV control is disabled) while `!orgResolved || !orgId`, so no lead is written under `"brewra"`/null**; `LeadStream` shows a loading state (not the empty-upload card) while org is resolving, and the empty card only on a genuine zero-result.
- **WS2:** `loadProfilerPagePayload` renders empty Current-ICPs on empty-success and only falls back to cache on read-failure; cache is cleared on empty-success; snapshot does not resurrect stale `existingICPs`.
- **WS3 (BE):** signature dedup — a regenerated ICP with the **same canonicalized `firmographics.industry` + `firmographics.segment`** as a dismissed one is excluded, and one with a materially different segment is *not* (the accepted bar); canonicalization collapses case / whitespace / punctuation; reject records the signature; the dismissed-set is per-user; an empty/missing `firmographics` signature is neither recorded nor matched (no over-suppression of firmographics-less ICPs). `patch-where-used` for the persistence layer — note `_reserve_unique_icp_id` is imported by `customer_profile.orchestrator`, so tests patch at the caller (`app.services.customer_profile.orchestrator._reserve_unique_icp_id`), **not** `app.services.icp.persistence` (per the review Observation / `docs/review-rubric.md → ## all`). **(FE):** a non-404 DELETE failure retains the pending-reject record and does not silently re-surface the card.
- **WS4:** `useCompanyProfile` surfaces a 5xx as `error` (does not resolve to `null`); `mapApiDataToCompanyProfileFields` maps a profile regardless of a mismatched/absent `user_id`.
